# TO2RENT — Микросервисная платформа Аренды Недвижимости

Полнофункциональная платформа для поиска и аренды элитной недвижимости, спроектированная в соответствии с принципами **SOLID**, с бэкендом на **C# (ASP.NET Core 9.0)**, базой данных **PostgreSQL**, шиной событий **Apache Kafka** и контейнеризацией **Docker / Docker Compose**.

---

## Архитектура и принципы SOLID

Микросервис разделен на изолированные слабосвязанные слои:

```
Backend/
├── Domain/                         # Чистые доменные модели и контракты
│   ├── Entities/                   # Сущности (Property, Booking, Review, Inquiry, User)
│   ├── DTOs/                       # Контракты данных (CreateBookingDto, PropertyFilterDto, AuthDto и др.)
│   └── Events/                     # Доменные события шины (BookingCreatedEvent, InquiryCreatedEvent)
├── Application/                    # Бизнес-логика и интерфейсы
│   ├── Interfaces/                 # IPropertyRepository, IBookingService, IAuthService...
│   └── Services/                   # BookingService, PropertyService, ReviewService, AuthService
├── Infrastructure/                 # Реализации для работы с БД и брокерами сообщений
│   ├── Repositories/               # EF Core реализации репозиториев
│   ├── Security/                   # PBKDF2 PasswordHasher & JWT TokenGenerator
│   ├── Messaging/                  # Confluent Kafka Producer & Background Audit Consumer
│   └── Data/                       # AppDbContext (Npgsql PostgreSQL + SQLite) & DbInitializer
└── Controllers/                    # Тонкие REST API контроллеры
```

### Реализация принципов SOLID:
1. **S (Single Responsibility Principle):**
   - Репозитории отвечают только за персистентность данных.
   - Сервисы отвечают за бизнес-логику (расчет ночей, валидация, публикация событий).
   - `KafkaEventPublisher` отвечает за сериализацию и отправку в брокер.
   - `KafkaBookingAuditConsumer` — фоновый сервис (`BackgroundService`) обработки очередей.
   - Контроллеры только обрабатывают HTTP-запросы/ответы.
2. **O (Open/Closed Principle):**
   - Добавление новых каналов уведомлений (Email, SMS, Telegram) реализуется добавлением новых потребителей Kafka без изменения сервиса бронирования.
3. **L (Liskov Substitution Principle):**
   - Любая реализация `IEventPublisher` взаимозаменяема без изменения вызывающего кода.
4. **I (Interface Segregation Principle):**
   - Тонкие сфокусированные интерфейсы: `IBookingRepository`, `IPropertyRepository`, `IReviewService`, `IInquiryService`, `IAuthService`.
5. **D (Dependency Inversion Principle):**
   - Контроллеры и сервисы зависят строго от интерфейсов-абстракций, внедряемых через .NET 9 DI-контейнер (`builder.Services.AddScoped<IBookingService, BookingService>()`).

## Пользователи и учетные записи (Аутентификация)

В системе реализована аутентификация на основе **JWT Bearer** токенов и ролевая модель доступа (**RBAC**). Пароли хешируются с использованием алгоритма PBKDF2 (HMAC-SHA256, 100 000 итераций).

При первом запуске базы данных автоматически создаются предустановленные аккаунты:

| Роль | Логин | Email | Пароль | Права и доступ |
| :--- | :--- | :--- | :--- | :--- |
| **Администратор** (`Admin`) | `admin` | `admin@to2rent.com` | `admin123` | Доступ к панели администрирования (`/Html-Pages/admin.html`), создание, редактирование и удаление объектов каталога, смена статусов бронирований, модерация отзывов, просмотр списка пользователей и аудит системы. |
| **Клиент** (`Client`) | `client` | `client@to2rent.com` | `client123` | Доступ к клиентскому функционалу: оформление онлайн-бронирования, автозаполнение контактов из профиля, отправка запросов брокерам, оставление отзывов. |

### Регистрация новых пользователей
Новый пользователь может зарегистрироваться через модальное окно на сайте, выбрав вкладку «Регистрация». При создании аккаунта можно назначить роль `Client` или `Admin`.

### Личный кабинет клиента («Мои бронирования» и Профиль)
Для авторизованных пользователей в шапке сайта доступна кнопка **«Личный кабинет»**:
- **Вкладка «Мои бронирования»**:
  - Отображение всех оформленных объектов недвижимости, дат заезда и выезда, количества гостей и итоговой стоимости.
  - Быстрые фильтры по статусу: *Все*, *Активные*, *Завершенные*, *Отмененные*.
  - Кнопка **«Отменить бронь»** для активных бронирований. Отмена автоматически переводит статус в `Cancelled` и инициирует событие `BookingStatusChangedEvent` в Apache Kafka.
- **Вкладка «Настройки профиля»**:
  - Редактирование ФИО, контактного телефона и email.
  - Безопасная смена пароля с проверкой текущего пароля (PBKDF2).

### Защита от овербукинга (Anti-Overbooking System)
Для предотвращения повторного бронирования одних и тех же дат реализована двухуровневая система проверки доступности:
1. **Клиентский уровень (Frontend):**
   - При открытии карточки бронирования подгружаются занятые даты выбранного объекта (`GET /api/properties/{id}/booked-dates`).
   - Отображаются информационные плашки со всеми зарезервированными интервалами.
   - При выборе пересекающегося диапазона дат интерфейс мгновенно выводит строгое предупреждение, подсвечивает поля ввода и блокирует кнопку «Подтвердить бронирование».
2. **Серверный уровень (Backend):**
   - Метод `HasOverlappingBookingAsync` в `BookingRepository` выполняет проверку пересечения временных интервалов: `CheckIn < BookedCheckOut && CheckOut > BookedCheckIn` для активных заявок со статусами `Pending` и `Confirmed`.
   - При попытке одновременного оформления сервер отклоняет запрос с кодом `409 Conflict` и сообщением об ошибке, предотвращая «состояние гонки» (Race Condition).

### Система отзывов и рейтингов объектов (Reviews & Rating System)
- **Привязка к объектам недвижимости:** отзывы могут относиться как к конкретному объекту каталога (`PropertyId`), так и к агентству в целом.
- **Расчет рейтингов:** эндпоинты `/api/properties/{id}/rating` и `/api/reviews/property/{propertyId}/summary` вычисляют точный средний балл (от 1 до 5) и количество отзывов.
- **Интерактивные виджеты на детальных страницах:** на страницах каждого дома и квартиры отображается рейтинг объекта, проверенные отзывы гостей и форма быстрой отправки отзыва с автозаполнением автора.
- **Страница отзывов (`comments.html`):** фильтрация отзывов («Все отзывы», «Об агентстве», «Об объектах») и выбор конкретного объекта из выпадающего списка при публикации.
- **Модерация в панели администратора:** просмотр привязки отзыва к объекту, одобрение/скрытие и удаление нежелательных записей в один клик.

### Избранное / Список желаемого (Favorites & Wishlist System)
- **Персистентность и синхронизация:** поддержка работы как для авторизованных пользователей, так и для анонимных гостей (`localStorage`). При входе в систему все сохраненные объекты автоматически мигрируют в учетную запись на сервере.
- **Интеграция с каталогом и карточками:** кнопки быстрого добавления в избранное в каталоге квартир, домов и на детальных страницах объектов с мгновенным визуальным откликом.
- **Вкладка «Избранное» в личном кабинете:** быстрый просмотр всех отобранных объектов, кнопка быстрого перехода к онлайн-бронированию или удалению из списка.
- **REST API:**
  - `GET /api/favorites/user/{userId}` — получение полного списка избранных объектов пользователя с метаданными.
  - `GET /api/favorites/user/{userId}/ids` — получение массива идентификаторов избранного для быстрой синхронизации состояния кнопок.
  - `POST /api/favorites/user/{userId}/{propertyId}` — добавление объекта в избранное.
  - `DELETE /api/favorites/user/{userId}/{propertyId}` — удаление объекта из избранного.

### Полнотекстовый поиск, сортировка и быстрые теги каталога (Catalog Search & Filters)
- **Многокритериальная фильтрация:** поиск по тексту (заголовок, город, описание), фильтр по городу, комнатам, этажам (`Floors`), диапазону цен (`MinPrice`, `MaxPrice`).
- **Расширенная сортировка:** поддержка порядков сортировки по умолчанию (новые), возрастанию/убыванию цены (`price_asc`, `price_desc`), площади (`area_desc`, `area_asc`), алфавиту (`title_asc`).
- **Быстрые теги (Quick Filter Chips):** ряд мгновенных кнопок быстрого выбора городов («Москва», «Минск», «Лондон», «Лос Анджелес»), ценовых диапазонов («До 500 $», «500 — 1000 $», «От 1000 $») и характеристик комнат/этажей.
- **Двусторонняя синхронизация URL (Deep Linking):** параметры фильтрации сохраняются в query-параметрах адресной строки через `history.replaceState`. Ссылками на отфильтрованный каталог можно делиться, и фильтры корректно восстанавливаются при перезагрузке страницы.
- **Отказоустойчивость:** при недоступности базы данных клиенты прозрачно переключаются на встроенный XML-парсер с идентичным набором фильтров и сортировок.

## Запуск через Docker Compose (PostgreSQL + Redis + Kafka + Микросервис)

В проект включен полный стек контейнеров:
- **PostgreSQL 16 Alpine** (порт `5432`)
- **Redis 7 Alpine** (порт `6379`)
- **Apache Kafka (KRaft mode)** (порт `9092`)
- **TO2RENT Microservice** (.NET 9 + Frontend) (порт `5000`)

### Запуск:
```bash
docker compose up -d
```

### Проверка статуса:
```bash
docker compose ps
```

После старта перейдите по адресу:
- **Сайт:** [http://localhost:5000](http://localhost:5000)
- **Панель управления (Админка):** [http://localhost:5000/Html-Pages/admin.html](http://localhost:5000/Html-Pages/admin.html)
- **Интерактивная документация API (Scalar):** [http://localhost:5000/scalar/v1](http://localhost:5000/scalar/v1)

Остановка:
```bash
docker compose down
```

## Что такое Apache Kafka и как она работает в проекте

### 1. Что такое Apache Kafka простыми словами
**Apache Kafka** — это высокопроизводительная распределенная шина сообщений (брокер событий).

Простая аналогия:
- Представьте центральное почтовое отделение или цифровую доску объявлений.
- **Producer (Отправитель)** отправляет письмо в определенный почтовый ящик (**Topic / Топик**), не заботясь о том, кто и когда его прочитает.
- **Consumer (Подписчик / Слушатель)** заглядывает в этот топик, забирает сообщения и выполняет свою работу (например, отправляет SMS клиенту, сохраняет запись в аудит-лог или передает данные в CRM).
- Главная фишка: отправитель и получатели **полностью независимы**. Если получатель временно выключен или перегружен, сообщения не теряются — они сохраняются в Kafka и будут прочитаны сразу после восстановления.

### 2. Зачем Kafka нужна в архитектуре аренды недвижимости
В микросервисной архитектуре клиент не должен ждать, пока сайт выполнит 10 сопутствующих задач (отправка Email, пуш в Telegram брокеру, расчет аналитики, логирование аудита).
1. Пользователь нажимает «Подтвердить бронирование».
2. Бэкенд мгновенно сохраняет заявку в БД и кидает событие `BookingCreatedEvent` в Kafka.
3. Пользователь сразу видит ответ «Бронирование принято» (задержка всего 20-30 мс).
4. Асинхронные микросервисы (почтовые сервисы, CRM, службы аудита) подхватывают это событие из Kafka в фоне.

### 3. Как Kafka настроена в TO2RENT
В проекте реализованы:
- **Топики (Topics):**
  - `to2rent-bookings` — события создания заявок и смены статусов бронирования (`Confirmed`, `Cancelled`, `Completed`).
  - `to2rent-inquiries` — события вопросов и запросов клиентов менеджерам.
- **Издатель (`KafkaEventPublisher`):** внедрен через интерфейс `IEventPublisher` по принципу Dependency Inversion (SOLID). Автоматически сериализует событие в JSON и публикует в брокер.
- **Фоновый обработчик (`KafkaBookingAuditConsumer`):** сервис `BackgroundService`, который слушает топики и обрабатывает входящие события в реальном времени.
- **Автоматическая отказоустойчивость (Graceful Fallback):** если Docker с Kafka не запущен (например, при быстром локальном старте через `run.bat`), сервис обнаруживает отсутствие брокера (`KafkaConnectivity.IsBrokerAvailable`), не падает с ошибкой, а безопасно переходит в резервный локальный режим In-Memory.

### 4. Запуск Kafka
При выполнении команды:
```bash
docker compose up -d
```
Docker автоматически разворачивает контейнер **Apache Kafka (KRaft mode)** на порту `9092` вместе с базой данных PostgreSQL и кэшем Redis.

## Распределенное кэширование Redis (L2 Cache)

Для обеспечения высокой скорости отклика каталога и аналитических запросов реализован уровень распределенного кэширования:
- **Интерфейс `ICacheService`:** инкапсулирует работу с кэшем (`GetAsync`, `SetAsync`, `RemoveAsync`, `RemoveByPrefixAsync`).
- **Слои кэширования:**
  - `properties:all` и `properties:filtered:*` — результаты запросов каталога (TTL: 5 минут).
  - `properties:single:{id}` — детальные карточки объектов (TTL: 10 минут).
  - `rating:summary:{id}` — сводные рейтинги объектов (TTL: 10 минут).
  - `stats:summary` — аналитические KPI дашборда (TTL: 60 секунд).
- **Инвалидация данных:** при создании, обновлении или удалении объекта недвижимости, создании бронирования или модерации отзыва кэш точечно сбрасывается по префиксам.
- **Отказоустойчивость (In-Memory Fallback):** если Redis не запущен или недоступен по TCP, приложение автоматически активирует встроенный `AddDistributedMemoryCache()`.

## Аудит нотификаций и поток событий Kafka

Для прозрачности асинхронных операций реализован сервис аудита `INotificationLogService`:
- **Потокобезопасный кольцевой буфер:** сохраняет последние 100 событий нотификаций в памяти приложения.
- **Каналы доставки:**
  - `Telegram Bot` — мгновенные оповещения менеджерам о новых бронированиях и запросах.
  - `Email Gateway` — подтверждения клиентам о бронированиях и изменении статусов.
  - `Kafka Bus` — распределенная шина событий между микросервисами.
- **Интерфейс в панели управления:** вкладка **«События Kafka»** с динамической таблицей времени события, типа, топика, канала доставки, получателя и содержания сообщения.

## Системная телеметрия и Health Checks

Для контроля состояния инфраструктуры добавлены эндпоинты мониторинга:
- `GET /api/system/status` — возвращает детальный статус всех компонентов:
  - Состояние СУБД (PostgreSQL / SQLite).
  - Состояние кэша (Redis / In-Memory).
  - Состояние шины событий (Apache Kafka Broker / In-Memory).
  - Потребление оперативной памяти процессом (RAM в МБ).
  - Аптайм приложения и текущая версия .NET.
- `GET /health` — стандартный эндпоинт ASP.NET Core Health Checks для систем оркестрации (Kubernetes, Docker Swarm, Consul).
- **Виджет в шапке панели управления:** статус-индикаторы БД, кэша, Kafka и памяти с цветовой индикацией.

## Экспорт данных в CSV (Microsoft Excel)

В панели управления доступны кнопки экспорта данных:
- **«Экспорт броней (CSV)»** — полная выгрузка истории бронирований (ID, клиент, контакты, объект, даты проживания, гостей, сумма, статус).
- **«Экспорт каталога (CSV)»** — полная выгрузка базы недвижимости (ID, заголовок, тип, город, цена, комнаты, площадь, этажность, описание).
- **Совместимость с Microsoft Excel:** генерация выполняется с добавлением префикса `\uFEFF` (UTF-8 Byte Order Mark), благодаря чему кириллические символы открываются в Excel без искажений.
